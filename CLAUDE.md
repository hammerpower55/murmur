# Murmur

Free, open source, fully offline voice dictation for Windows on ARM64 (Snapdragon X) and Apple Silicon Macs. Hold a hotkey, speak, release, and clean text is pasted into the focused app. The full build spec lives outside the repo; this file keeps the rules every session must follow.

Build phases run in order. Each phase ends with its acceptance checks, one commit, and a stop for review.

## Hard constraints (never violate)

1. Windows ARM64 and Apple Silicon macOS only for anything shipped. Every released binary, dependency and artefact is `aarch64-pc-windows-msvc` or `aarch64-apple-darwin`. No x64 binaries in a release, and no Intel or universal Mac builds: no x64 ONNX Runtime DLLs, sidecars or NSIS plugins. If a crate cannot build for aarch64, replace it. Never fall back to x64 emulation or Rosetta. A local x64 development build on an Intel or AMD Windows machine is allowed, and only that: `docs/x64-local.md`, `scripts/x64_env.ps1` and `src-tauri/tauri.x64.conf.json` build and run a copy there, while CI, tagging and the packaging scripts stay ARM64 only.
2. Offline by default. The only network request is downloading a model the user clicked Download on. No telemetry, analytics, update pings, accounts or cloud transcription.
3. All user data (transcripts, stats, dictionary, snippets, settings) stays in `%APPDATA%\Murmur` (`~/Library/Application Support/Murmur` on macOS; every `%APPDATA%\Murmur` below means that folder there). Transcripts live in SQLite only.
4. Microphone audio is never written to disk unless "Keep audio clips" is on (default off).
5. UI copy: no em or en dashes, one clean line telling the user what to do, no subtext, no exclamation marks, sentence case.
6. Decisions in the spec are final. If truly blocked, stop, state the blocker in one paragraph, propose exactly one fix.
7. The app name lives in exactly two places: `src-tauri/tauri.conf.json` `productName` and `APP_NAME` in `src/lib/app.ts`. Everything else reads from those.

## Stack

- Tauri 2, Rust edition 2021, React 18 + TypeScript + Vite, Tailwind CSS 4. Shaped like Handy (github.com/cjpais/Handy) so its code is a usable reference.
- Speech: whisper-rs (whisper.cpp, CPU with NEON, no CUDA or OpenBLAS) for Whisper GGML; `ort` (ONNX Runtime 1.19+, prebuilt win-arm64, CPU EP) for Parakeet, Moonshine, SenseVoice. Vulkan is a Phase 9 stretch goal. QNN runs the word fixer on the Snapdragon X NPU where there is one (see the NPU decision below); everything else, and every PC without that NPU, stays on the CPU.
- ONNX Runtime: Microsoft's official `onnxruntime-win-arm64-1.31.0.zip` (pure ARM64, never the arm64x package, which contains x64 code), fetched into git-ignored `src-tauri/vendor/` by `scripts/fetch_onnxruntime.ps1` (SHA-256 checked). That script's `-Arch x64` fetches the x64 zip instead, for the local x64 build only. `ort` =2.0.0-rc.15 with `load-dynamic`: the DLL is loaded from an explicit path (bundle resource, or the vendor copy in debug builds) because Windows ships an older onnxruntime.dll in System32.
- Models: `src-tauri/src/models/catalog.json` is the catalogue; URLs are pinned to a repository commit and every file has a SHA-256 (or a git SHA-1 for small git-stored files). Downloads go to `%APPDATA%\Murmur\models\<id>\` as `name.part`, resume with HTTP Range, and are renamed into place only after the hash matches. `engine::host::EngineHost` holds the active engine; switching unloads the old model before loading the new one so two large models are never resident together.
- Settings: `%APPDATA%\Murmur\settings.json` through tauri-plugin-store given an absolute path (its default would be `%APPDATA%\<identifier>`).
- History: `%APPDATA%\Murmur\history.db` (rusqlite bundled, WAL, schema versioned with PRAGMA user_version in `db/schema.rs`). One connection behind a mutex shared by the dictation thread and the commands. A row is written even when pasting fails, so the text can be copied from History. `word_counts` is updated in the same transaction as each insert and delete (stopwords from `text/stopwords.json` excluded). App icons are extracted from the exe on first use and saved to `%APPDATA%\Murmur\icons\<exe>.png`.
- Audio: cpal at device rate, resampled to 16 kHz mono f32 with rubato. The input stream is built at startup and kept paused between dictations (building takes 250 to 500 ms, play is instant); it is rebuilt when cpal reports the device changed.
- Hotkey events are timestamped inside the hook. The state machine uses those timestamps, never the time the controller got to them.
- Hotkey: our own `WH_KEYBOARD_LL` hook via the `windows` crate (`src-tauri/src/hotkey/listener.rs`), for key down and key up. Do not use tauri-plugin-global-shortcut for the main hotkey. Do not use rdev: its hook calls `AttachThreadInput` and `ToUnicodeEx` on every key, which stalls when the focused window is busy (Windows then skips the hook and the key leaks) and breaks dead keys. The hook proc must stay fast and never block; input Murmur injects is tagged with `MURMUR_INPUT_TAG` in `dwExtraInfo` so the hook ignores it.
- Injection: arboard + enigo. Save clipboard, write text, Ctrl+V (Ctrl+Shift+V for terminals), wait 120 ms, restore clipboard.
- Sounds: rodio playing bundled WAVs from `src-tauri/sounds`.
- DB: rusqlite with `bundled`. Settings: tauri-plugin-store `settings.json`. Frontend state: zustand. Charts: recharts.
- Packaging: NSIS arm64 installer `Murmur_<version>_arm64-setup.exe` plus portable zip; on macOS `Murmur_<version>_aarch64.dmg`.
- Tests: `cargo test`, vitest. No end to end framework.
- `.cargo/config.toml` pins the build target to aarch64 and sets `LIBCLANG_PATH`. LLVM `bin` must also be on PATH (some C deps call `clang` directly).
- whisper.cpp refuses MSVC on ARM, so `.cargo/config.toml` also makes whisper-rs-sys build it with LLVM `clang-cl` through native ARM64 Ninja (winget `Ninja-build.Ninja`), adds back `/EHsc`, and forces `CMAKE_BUILD_TYPE=Release` so dev timings match release. cargo does not rebuild whisper-rs-sys when these change: `cargo clean -p whisper-rs-sys`.

## Decisions made during the build (deviations from the spec, approved)

- Default model is `ggml-large-v3-turbo-q8_0.bin` (models\whisper-large-v3-turbo-q8), not q5_0. ggml repacks Q8_0 weights for i8mm at load; Q5_0 has no repacked ARM kernel. q5_0 took 10 to 14 s for a 5 s clip on the X Plus, q8_0 takes about 4.5 s with the same accuracy. Measured RAM with q8_0 loaded: 1.28 GB working set, 1.75 GB private after a dictation.
- Whisper always encodes its full 30 s window. Shrinking it with `audio_ctx` was 3x faster but garbled Roman Urdu and repeated sentences on real recordings. Do not reintroduce without rerunning the fixture WER check.
- Whisper output that is just a run of three or more words copied from the initial prompt is dropped (it happens on silence).
- `ROMAN_URDU_PROMPT` is all Roman Urdu, not the spec's mixed English and Roman Urdu prompt. With the spec prompt and English forced, Whisper translated or dropped Urdu heavy sentences (mixed fixture WER 71%, users saw English translations). The all Roman Urdu prompt gives 17.7% raw and 12.9% after the text pipeline, English unchanged at 6.1%, about 0.7 s slower per clip. Forcing hi or ur with the same prompt gives the same text and is slower; without the prompt they write Devanagari or Urdu script. `cargo test roman_urdu_strategies -- --ignored --nocapture` compares the options.
- Fixture clips: debug builds with `MURMUR_FIXTURE_DIR` set save each dictation as the next free `clip_NN.wav` and skip transcription. Release builds never write audio.
- The overlay window is never hidden. It stays shown, transparent, click through and non focusable (`focusable: false` gives WS_EX_NOACTIVATE; click through gives WS_EX_TRANSPARENT | WS_EX_LAYERED), and the page draws nothing when idle. Hiding it breaks things: WebView2 stops rendering hidden windows, and showing a window through Tauri activates it and steals focus. Placement uses Win32 `SetWindowPos` with SWP_NOACTIVATE. Idle CPU with overlay and sound output open: about 0.25%.
- Keys typed into Murmur's own window never reach a low level keyboard hook (Murmur's or any other process's): focus sits in WebView2's msedgewebview2.exe input window, and Windows does not pass that input through WH_KEYBOARD_LL. Reinstalling the hook does not help. So Settings records hotkeys in the page (`recordHotkey` in `src/lib/keys.ts`, names matching `hotkey/keys.rs`) while `hotkey_recording` makes the global hook stand aside, and the dictation hotkey does nothing while Murmur's window is focused.
- Testing with injected keys: keep Notepad (never this chat app, never Murmur) in front; anything the mic hears gets pasted into the focused app. SendInput with only a virtual key gives browser key events an empty `code`, so the page falls back to `keyCode`.
- Moonshine Base uses the int8 "merged" ONNX build from UsefulSensors/moonshine (63 MB of weights plus tokenizer.json from the float folder; the float build is 247 MB). Its decoder's cache inputs (8 layers, 8 heads of 52) are read from the model, the first step runs the no cache branch with placeholder past tensors, and the cross attention cache from that step is reused. SenseVoice Small is sherpa-onnx's model.int8.onnx: Kaldi fbank (`engine/fbank.rs`, Hamming window, 16 bit scale input), low frame rate stacking 7/6, CMVN and language ids from the model metadata, CTC greedy after the 4 tag frames, text normalisation on (so "three" can come back as "3").
- Measured on the fixture clips (X Plus, AC, English): Moonshine Base 10.6% WER at about 0.2 s per clip; SenseVoice Small 6.1% at about 0.13 s. Neither handles Roman Urdu.
- Settings (`settings.rs`) are one record stored as one key per field in settings.json; each key is validated alone so a bad value only resets itself. The live copy is `settings::Shared` (Arc<RwLock>), read by the dictation thread on every dictation; `set_settings` saves, swaps it and pushes changes to the hook, recorder, overlay, sounds, tray, autostart and (Roman Urdu only) a Whisper reload for the prompt.
- Hotkeys are stored as key names (`hotkey/keys.rs`): ctrl, alt, shift, win match either side; a hotkey needs a modifier plus another key, or only function keys. Settings records a hotkey through the hook itself (`HotkeyControl::capture`), because the webview never sees Win and must not receive the keys. The hook proc only ever try_locks the control.
- Dictionary, snippets and the Roman Urdu table live in `dictionary.json`, `snippets.json` and `roman_urdu.json` in %APPDATA%\Murmur (`text/store.rs`). The Roman Urdu file exists only once edited; "Restore defaults" deletes it.
- "Unload model when idle" parks the model in `EngineHost` (unloaded but still active); the next hotkey press starts loading it while the user speaks.
- "Keep audio clips" writes `%APPDATA%\Murmur\clips\<transcript id>.wav`; deleting a transcript or clearing history deletes the clips.
- Tray via Tauri's tray-icon feature (`tray.rs`); the recording icon is the app icon with a red dot drawn at startup. Launch at login uses tauri-plugin-autostart (HKCU Run key) with `--hidden`, which starts in the tray. The main window starts hidden and is shown in setup unless started hidden with the tray on. Closing it hides to the tray when "Close to tray" is on, otherwise quits.
- Measured on the fixture clips (X Plus, AC): Parakeet v2 transcribes a 5 s clip in about 0.1 to 0.16 s with 1.5% English WER, but cannot do Roman Urdu; Whisper turbo Q8_0 takes about 4.5 s with 6.1% English WER and is the only usable Roman Urdu option.
- Smart formatting (`text/smart.rs`, setting `smartFormatting`, default on) follows what Wispr Flow documents, as offline rules: Backtrack ("at 2 actually 3", "Tuesday, no, Wednesday", "scratch that") runs before filler removal and only fires between values of the same kind; spoken line and paragraph breaks ("new line" only at a pause); numbered lists from one/two, 1./2., first/second, "number one", and bullets from "bullet point", needing a pause after each marker or three or more short items; lists said without numbers (`implicit_lists`): a sentence of three or more comma parts opening the same way ("I need X, I need Y, I need Z"), a colon followed by short items or by short sentences, short sentences after one containing "the following", or three or more short sentences opening the same way; items keep their words; paragraph breaks at transitions in long dictations; email greeting and sign off lines and no closing full stop on short chat messages, by `AppKind` from the target exe and browser title. `smart_formatting_on_history` (ignored test) replays the local history to catch false positives.
- Insights (`db/insights.rs`) are computed in SQL on each request and cached in the `useInsights` store, refreshed on `transcript-added` and after Clear history. Weeks start Monday; last week is compared over the same number of days. Average speed is words over audio minutes for the last 30 days. Time saved is total words at the `typingWpm` setting (default 40) minus total audio time, never below zero. Streak counts consecutive days back from today (`db/stats.rs`), so it is 0 until the first dictation of the day.
- Insights fixture: `py tests/seed_insights.py` writes 200 transcripts anchored to today to `%TEMP%\murmur-insights-fixture.db` and prints the expected numbers; run a debug build with `MURMUR_HISTORY_DB` set to that path to check the page. The same fixture is the `two_hundred_transcript_fixture` unit test.
- Packaging: NSIS only (`bundle.targets`), per user install, WebView2 bootstrapper skipped (Windows 11 ships WebView2, and the bootstrapper is not ARM64). NSIS has no ARM64 stub, so the setup and uninstall wrappers are 32 bit x86, as are NSIS's own plugins in `$PLUGINSDIR` (nsDialogs, StartMenu, System, nsis_tauri_utils), which run during setup and are never installed; every binary installed is ARM64. Release CI unpacks the installer with 7-Zip and checks that payload. `scripts/verify_arm64.ps1` reads PE headers and fails on anything else (`-AllowX86Installer` accepts only the `*-setup.exe` stub). `scripts/package_portable.ps1` builds `<productName>_<version>_arm64-portable.zip` with NOTICE and LICENSE next to the exe, where Settings > About looks for them.
- Release CI (`.github/workflows/release.yml`) runs on `windows-11-arm` on a `v*` tag, with LLVM (woa64 MSI) and Ninja (winarm64) pinned by SHA-256, runs both test suites, builds, checks ARM64 and attaches the installer and zip to the release. `SOURCE_URL` in `src/lib/app.ts` is empty until the repository is public.
- More catalogue models (no engine changes): Whisper Tiny, Base and Small Q8_0 (multilingual), Small and Medium English Q8_0, Moonshine Tiny (English, int8) and Moonshine Tiny Arabic, Chinese, Japanese, Korean, Ukrainian and Vietnamese (float, Moonshine AI Community License; Korean has its own tokenizer.json, the rest share English's). English only Whisper builds never get the Roman Urdu prompt. Moonshine allows 13 tokens per second of audio, double the reference, because the CJK models spend a token or more per character and were cut off mid character. Measured on the fixture clips: Moonshine Tiny 6.1% English WER at about 0.12 s, Whisper Tiny Q8_0 9.1% English and 38.7% mixed after clean up at about 0.25 s, Parakeet v2 1.5% versus v3 3.0% English.
- macOS on Apple Silicon (asked for by the user, replaces "Windows ARM64 only"): a second target, `aarch64-apple-darwin`, macOS 14 or later (ONNX Runtime 1.31's minimum). Windows code is unchanged; each Win32 part has a counterpart behind `#[cfg(target_os = "macos")]`, as a `_mac.rs` file where the whole file differs (`hotkey/listener_mac.rs`, `hotkey/vk_mac.rs`, `inject/field_mac.rs`, `overlay/window_mac.rs`) and shared FFI in `macos.rs`. Hotkey: a Quartz event tap (session, head insert, key down, key up and flags changed), timestamped in the tap and fed to the same `Hook` as the Windows hook; Mac key codes are translated to Windows virtual keys so `hotkey/keys.rs` names and the tests are shared (Command is "win", Option is "alt", shown as Cmd and Option in the page); the tap is switched back on when macOS disables it for a slow callback. It needs the Accessibility permission: the hotkey thread asks once (the system dialog) and retries every 2 s until granted. Paste is Command+V by key position (kVK_ANSI_V, looking keys up by character needs the main thread), tagged through `event_source_user_data`, terminals included. The target app is NSWorkspace's frontmost app, named by its bundle ("Slack.app", which AppKind and the terminal list know) with the focused window title read through Accessibility; icons come from NSWorkspace. The field reader uses AXUIElement (focused element, AXSelectedTextRange, AXStringForRange), skips AXSecureTextField and Murmur's own process. The overlay is placed with Tauri on the display under the mouse (work area above the Dock) and raised to status window level on every Space and over full screen apps; transparency needs no private API flag since Tauri 2.12.1. Whisper uses Metal (whisper-rs `metal`, shaders embedded); everything else stays on the CPU. ONNX Runtime is Microsoft's `onnxruntime-osx-arm64-1.31.0.tgz` (signed, arm64 only), fetched by `scripts/fetch_onnxruntime.sh` (SHA-256 checked) and bundled in Contents/Frameworks. QNN is Windows only; on macOS the qnn folder never exists, so `npu_available` is false and NPU models are never listed. Microphone permission: the system prompt with `NSMicrophoneUsageDescription` from `src-tauri/Info.plist`. Launch at login is tauri-plugin-autostart's LaunchAgent; the Dock icon brings back a window hidden to the menu bar. Build: `source scripts/macos_env.sh` first (it overrides the Windows target and clang-cl settings in `.cargo/config.toml`), then `cargo test` or `pnpm tauri build --target aarch64-apple-darwin`. `tauri.macos.conf.json` swaps the NSIS target and Windows DLLs for app and dmg. Builds are ad hoc signed, not notarised, so first launch needs right click, Open; Developer ID signing and notarisation need an Apple Developer account. The `macos` job in release.yml (macos-14, Apple Silicon) runs both test suites, builds the dmg, checks every Mach-O file is arm64 only and attaches the dmg on a tag; `gh workflow run release.yml -f platforms=macos` runs it without a tag. Built and tested only on GitHub's runner so far, never on a real Mac.
- Parakeet Unified EN 0.6B (NVIDIA, April 2026, NVIDIA Open Model License) is an RNN-T model, read from sherpa-onnx's int8 export (encoder, decoder, joiner, tokens.txt, pinned to csukuangfj2's commit) with v2's nemo128.onnx for features; `engine/parakeet.rs` picks RNN-T greedy decoding when joiner.int8.onnx is present (every frame visited, blank start, at most 10 tokens per frame). Measured on the fixture clips: 0.0% English WER (v2 1.5%, one word), 77.4% mixed (v2 87.1%, neither usable for Roman Urdu), 0.2 to 0.36 s per clip (v2 0.16 to 0.19 s), 806 MB peak working set.
- Fix misheard words (setting `fixMisheardWords`, default on, needs a "Word fixer" download, catalogue family `fixup`) only ever swaps in the user's own words: dictionary written forms and words from the text before the cursor (UI Automation, `inject/field.rs`, read while the user speaks) or the last dictation into the same app within 10 minutes. `text/fixup.rs` finds runs of one to three transcript words that sound like one of them (`sounds_alike`: spelling distance or a consonant key, runs never start or end on a stopword); only then does `engine/fixer.rs` score the text both ways with the model and swap when the user's word is at least e^3 more likely (e^1.5 for dictionary words). Roman Urdu dictations are skipped: one word that is only Roman Urdu is enough (the spec list plus `MORE_ROMAN_URDU`, detection only), because English models mishear Urdu into nonsense the fixer made worse ("Such memo ji but a gallery" to "smaller", "Munja pata honerale" to "generated"). Fillers are never candidates or suspects (the fixer runs before filler removal; "Um" became "Im"), and a run of heard words is never replaced by one of its own words ("private season" became "private"). Open ended fixes were tried and rejected: a rewrite prompt (1.7B and 4B) missed real errors, reworded text and invented new ones ("dice cards"); an edit list prompt found almost nothing; rescoring against the model's own likely words fixed "beater" but also turned "weather" into "water" and "place" into "face". The constrained version fixes all four real cases in `fixup_eval` (chance, beta, Kubernetes, Maaz), none of the traps, changes 1 of 26 history items, and costs about 70 ms only when a candidate exists. It loads in about 5 s when a dictation starts and holds about 2.1 GB peak working set, freed with the speech model by "Unload model when idle". `cargo test --release fixup_eval -- --ignored --nocapture` reruns it; do not widen the candidates without it. Swaps are stored with the transcript (`fixed_words`, JSON, schema version 2) and shown in History as "Fixed heard to meant".
- Word fixer models: Qwen3 4B Instruct 2507 (robinsmits' onnxruntime-genai cpu int4 export, Apache 2.0, pinned commit, 2.55 GB) is listed first and used whenever installed; Qwen3 1.7B (onnx-community, 1.4 GB) stays as the lighter choice for 8 GB PCs. `registry::fixup_id` picks the first installed in catalogue order and `ModelsView.fixer` tells the page which one shows "On". Phi-4-mini was rejected: its cpu int4 build is 4.9 GB (the 200k vocabulary is stored unquantised). Measured with the 4B: own words mode 4 better, 0 worse, about 160 ms when a candidate exists; every word mode 6 better, 0 worse (adds "dance cards" to "chance cards" in a long dictation, which the 1.7B scored +0.4), 3 of 44 history items changed, about 1.1 s average and up to 2.4 s on long dictations (1.7B: 0.46 s); traps score further from the threshold (weather to water +2.5 against +6.5). Peak working set 2.4 GB (1.7B 2.1 GB). Chat 12 to 18 tokens per second. Both models run on the CPU on any ARM64 PC; any NPU path added later must keep this CPU path as the fallback, because Murmur is released for PCs without a Snapdragon NPU.
- NPU (asked for by the user, replaces "QNN off by default"): Qualcomm's onnxruntime-qnn 2.7.0 plugin (Windows ARM64 wheel from PyPI, pinned and SHA-256 checked by `scripts/fetch_qnn.ps1` into git-ignored `vendor/onnxruntime-qnn-2.7.0`, bundled as `qnn\` next to the exe) is registered with the stock ONNX Runtime 1.31 through `Environment::register_ep_library`; `onnx::npu_available` checks once (off the main thread at startup) that it loads and reports a Hexagon NPU. Only what precompiled models need ships (plugin, QnnHtp, QnnSystem, the V73 stub, skel and catalog file, 25 MB); QnnHtpPrepare (93 MB, on device compilation) is left out. Every DLL is ARM64; the .so is Hexagon DSP code. Qualcomm's AI Stack License allows shipping it inside the app, not on its own, and its license files ship with it. NPU builds are catalogue entries with `"npu": true`, listed only where `npu_available` and used only while `useNpu` (default on) is set; `registry::fixup` orders NPU builds first, then CPU ones, and `FixupModel::fallback` loads the next if one fails (an NPU it was not compiled for). The NPU word fixer is llmware's Qwen2.5 1.5B Instruct QNN build (Foundry Local's format, compiled for the X Elite's V73, runs on the X Plus): embeddings and lm_head on the CPU, context_ctx (64 token window) and iterator_ctx (one token) as QNN graphs with attention and a float cache on the CPU between them, so `llm.rs` shares everything above `run_with`. A window costs about 50 ms and a single token about 30 ms, so anything over one token runs as a padded window. A catalogue `open_gain` raises the every word bar per model: 10 for the 1.5B, whose wrong swaps on the history ("animations" to "actions" +8.1, "private" to "climate" +9.4) scored around its right ones ("dance" to "chance" +8.6), so it gives up that one. Measured: own words mode 5 better, 0 worse, 72 ms average (also fixes "clari tree" to ClariTree, which the CPU models scored just under the line); every word mode (with the bar at 10) 6 better, 0 worse, about 1 s, 3 of 65 history items changed, all already garbled; chat about 21 tokens per second but noticeably weaker than the CPU 4B; 2.0 GB working set, 0.5 GB private. Rejected: llmware's Qwen2.5 7B QNN build (5.9 GB working set, about 1.8 s per dictation in every word mode, 2 wrong swaps), Phi-3.5 mini and Llama 3.2 3B QNN builds (not tried, weaker than Qwen at their size), a Qwen3 4B Genie build (compiled for the phone V79 NPU), llama.cpp's Hexagon backend (needs test signing). Speech on the NPU: see the NPU Whisper decision.
- NPU Whisper (asked for as "wyoming-distil-whisper with npu"; Wyoming is Home Assistant's network protocol for a separate Python server and is not used, Murmur runs the models in process): `engine/whisper_npu.rs` runs Qualcomm AI Hub's Whisper ONNX exports (release v0.66.0, public S3 zips pinned by path and SHA-256, unpacked by the downloader's `unzip` files) with tokenizer.json from the original Hugging Face repos. Encoder: 30 s of log mel (`engine/whisper_mel.rs`, Whisper's own recipe) to each layer's cross attention cache; decoder: one token at a time with a 199 slot self cache the model shifts itself, a 200 long mask opened from the end (-100 closed) and the position. Prefix: `<|startofprev|>` + prompt (at most half the 200 positions), start, language and task for multilingual builds, no timestamps; greedy over text tokens and the end token, no end token first; audio over 30 s in 30 s pieces; Whisper's prompt echo rule applies. Floats follow the build (Turbo is fp16 throughout, `half` feature of ort). A build with a .bin beside each graph is precompiled; anything else is compiled for the NPU on first load (QnnHtpPrepare, about 40 s for Distil) and saved as *_compiled.onnx (about 4 s later). `engine::host::engine_for` picks it for a Whisper folder holding encoder.onnx, and both are hidden on PCs without the NPU like the NPU word fixer. Measured on the fixture clips (X Plus): Distil-Whisper Small English (distil-small.en, plain fp32 ONNX): 6.1% English WER at about 0.45 to 0.7 s per clip, 83.9% mixed (English only), 2.5 GB working set, 2.4 GB private. Whisper Large V3 Turbo (precompiled for the X Elite, runs on the X Plus): without a prompt about 0.75 s per clip and English right but Roman Urdu translated; with the Roman Urdu prompt (as Murmur runs it) 10.6% English and 38.7% mixed at about 1.7 s, against 6.1% and 12.9% at about 4.5 s for whisper.cpp Q8_0 on the CPU; the prompt costs about 0.9 s because its 70 tokens run through the decoder one at a time; clip_08 came back empty because the speech repeats a prompt line and the echo rule dropped it. 2.3 GB working set, 0.1 GB private (the contexts are mapped). Parakeet v2 on the CPU stays faster and more accurate for English (1.5% at about 0.15 s).
- Downloads check free space first (`GetDiskFreeSpaceExW`, keeping 512 MB spare) and fail with "Free up N GB of disk space to download this model." before writing anything.
- "Check every word" (setting `fixAnyWord`, default off) also lets the model propose its own word: up to four plain non stopword words it finds least likely (log probability below -5) are compared with up to four sound alike words from its 2000 most likely tokens there, and a swap needs e^8 (weather to water scored +6.5, place to face +7.1). A word that sounds like one of the user's own is left to that path, so the model's guess cannot beat a dictionary name ("mars" became "Maria" before). Measured: 5 better and 0 worse on `fixup_eval` (beater to beta with no context), 3 of 42 history items changed, all already garbled; about 0.2 to 1.1 s on every dictation. `MURMUR_FIXUP_ANY=1` runs `fixup_eval` in this mode. Turning "Fix misheard words" off frees the model at once.
- Chat (`chat.rs`, nav page) talks to the word fixer's model directly so it can be tried out: Qwen markup, with an empty think block only for catalogue entries marked `thinking` (Qwen3 1.7B is hybrid and needs it to stop thinking; the 4B Instruct 2507 ended its reply at once when given one, so "hey" got no answer), greedy with a 1.15 repeat penalty over the last 64 tokens, 512 token replies, oldest messages dropped past 3000 prompt tokens, streamed as `chat-text` and ended by `chat-done`. Nothing is saved. The model is locked per token, so a dictation can still be fixed while a reply is written. About 30 tokens per second with the 1.7B on the X Plus, 12 to 18 with the 4B.
- Learn words (setting `learnWords`, default on): after a paste the field is watched for 60 s (until focus moves or the next dictation); `text/learn.rs` aligns the pasted words against the field and adds a dictionary entry, marked `learned`, for an edit of one to three words that sounds like what was heard and looks like vocabulary (capitals or digits not explained by a sentence start, or words joined or split). Plain word swaps ("by" to "buy") and rewrites are never learned, and existing entries win. Password fields, Murmur's own windows and terminals are never read; nothing read is stored except the learned entry. Each learn emits `words-learned`, shown as a note in the corner of the main window that opens Dictionary.
- Downloads retry each source three times on a dropped connection, resuming with Range, and a file may list `mirrors` (same bytes, hash checked) that are tried when the main URL fails or runs under 100 KB/s after 8 s. Hugging Face measured about 20 to 35 KB/s from the developer's connection while ModelScope ran at 0.3 to 1.2 MB/s.
- WER check: `cargo test fixture_wer -- --ignored --nocapture` (needs the model and the clips in `tests/audio`, which are the developer's own voice and git-ignored, so they exist only on that machine; `MURMUR_MODEL_ID` picks a catalogue model). Timings are only meaningful on AC power with the machine quiet; a rebuild in this OneDrive folder triggers OneDrive and Defender scans that slow it 2x.

- Local x64 build for development (asked for by the user): `docs/x64-local.md` builds the same source as `x86_64-pc-windows-msvc` on an Intel or AMD Windows machine, with `scripts/x64_env.ps1` for the portable toolchain, `scripts/fetch_onnxruntime.ps1 -Arch x64` for Microsoft's x64 runtime, and `--config src-tauri/tauri.x64.conf.json` to replace the ARM64 and QNN bundle resources (config merge keeps the base resource map, so the overlay sets its own list). `engine::onnx::VENDORED_RUNTIME` names the vendor folder by target architecture, and `lib.rs` looks for `vendor/<runtime>/lib/onnxruntime.dll` under the resource root too, so the installer carries the DLL. No NPU there, since QNN is ARM64 Qualcomm only. Two traps: MSVC `cl.exe` fails inside cargo build scripts on that machine with C1083 "Permission denied" on its temporary file while the same command succeeds by hand, so every C and C++ compile goes through LLVM's `clang-cl` (`CC_x86_64_pc_windows_msvc`), and an NSIS installer run from a OneDrive folder fails with "Error writing temporary file" (copy it to a local folder first). Nothing x64 is released: CI, `scripts/verify_arm64.ps1` and `scripts/package_portable.ps1` still accept ARM64 only.

## Architecture

```
src/            React frontend
  app/          routes: Home, Insights, History, Models, Dictionary, Snippets, Settings
  overlay/      floating pill window (separate Vite entry)
  components/  store/ (zustand)  lib/ (invoke wrappers, formatting)
src-tauri/src/
  audio/        capture, resample, vad, levels
  engine/       mod.rs (SpeechEngine trait), host, onnx (shared runtime), fbank,
                whisper, parakeet, moonshine, sensevoice, llm + fixer (word fixer)
  models/       catalog.rs + catalog.json, download, registry
  hotkey/       listener (WH_KEYBOARD_LL hook), state (push to talk + toggle), keys
  inject/       paste, focus, field (UI Automation reads of the focused field)
  text/         fillers, dictionary, snippets, format, store (user lists),
                fixup (misheard word candidates), learn (words from corrections)
  db/           schema, transcripts, stats, insights
  overlay/      window, events
  sound/        player
  commands.rs   all #[tauri::command] fns
  dictation.rs  the controller thread
  tray.rs
  settings.rs
src-tauri/sounds/   start.wav, stop.wav, cancel.wav
scripts/gen_sounds.py
tests/
```

One dictation:
1. Hotkey down: state Recording, play start.wav, show overlay, start capture 60 ms after playback starts.
2. Every 50 ms emit `audio-level { rms, peak }` to the overlay.
3. Hotkey up (or second press in toggle mode): state Processing, stop capture, then play stop.wav.
4. Under 300 ms or all silence: state Cancelled, play cancel.wav, hide overlay, record nothing.
5. Active engine transcribes the 16 kHz buffer, then the word fixer swaps misheard words for the user's own (when on and downloaded).
6. Text pipeline in this order: trim, filler removal, dictionary, (Roman Urdu normalisation), snippets, capitalisation and spacing.
7. Inject into the focused app, then watch the field for corrections to learn (when on).
8. Insert transcript row, emit `transcript-added`.
9. Overlay shows done for 400 ms, then hides. State Idle.

Escape while Recording cancels. Hotkey states: Idle, Recording, Processing, Cancelled, Error, every transition unit tested.

Engine trait:

```rust
pub trait SpeechEngine: Send + Sync {
    fn id(&self) -> &'static str;
    fn load(&mut self, model_path: &Path, opts: &EngineOptions) -> Result<()>;
    fn unload(&mut self);
    fn is_loaded(&self) -> bool;
    fn transcribe(&self, pcm16k_mono: &[f32], language: Option<&str>) -> Result<Transcript>;
}
```

The active model loads once at start (or on switch) and stays in memory; "Unload model after idle" (default 10 min, 0 = never) frees it.

## Quality bar

- `cargo clippy --target aarch64-pc-windows-msvc -- -D warnings` clean.
- `cargo test` and `pnpm test` green at every commit.
- No `unwrap()` outside tests. Errors surface in the UI as one line.
- Idle: under 1% CPU, under 150 MB RAM with model unloaded; under 1.2 GB with whisper-large-v3-turbo-q5 loaded (the q8_0 default measures 1.28 GB working set); never above 3 GB with any catalogue model.
- Hotkey down to pill visible under 100 ms. Key up to pasted text under 3 s for a 10 s clip on the default model, under 1.5 s with Parakeet v2.
- `tests/audio/` holds 10 reference clips (5 English, 5 English + Roman Urdu). Every engine change reruns them and prints WER.
- Every screen handles its empty state with one line of copy.
- UI design context (audience, personality, the one amber accent, motion rules) is in `.impeccable.md`. Motion tokens, keyframes, `.surface`, `.lift` and `.stagger` live in `src/index.css`; animate transform and opacity only, and everything must still work under prefers-reduced-motion.
